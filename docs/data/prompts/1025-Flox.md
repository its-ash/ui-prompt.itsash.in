# Landing Page Build Prompt — Flox Theme (Fictional Brand)

You are a senior front-end engineer. Build a complete, production-ready landing page using the Flox visual style specification below. **Invent a fictional brand name, product, and all copy. Never use the real brand name "Flox", its logo, trademarks, or product names anywhere in the page.** Use the style only.

## 1. STRICT ARCHITECTURE RULES

**1.1 CSS-First & Zero Inline CSS**
- All styling lives in a dedicated `style.css`. No `style="..."` attributes in HTML.
- Target all design via class/ID selectors only. Keep HTML semantic and styling-agnostic.

**1.2 CSS Variables & Theme Tokens**
Store every visual token in `:root` (and theme classes) as CSS variables:

Colors:
- `--color-graphite-ink: #020817;`
- `--color-hairline-slate: #e2e8f0;`
- `--color-paper-white: #ffffff;`
- `--color-carbon: #1b1b1b;`
- `--color-mist: #f3f3f3;`
- `--color-obsidian: #0c0c0c;`
- `--color-iris-glow: #8247ff;`
- `--color-magenta-pulse: #f47bff;`
- `--color-ember-orange: #ff8a3d;`
- `--color-rose-hot: #ff4fae;`

Theme tokens (map to the system's required generic tokens):
- `--primary: #8247ff;` `--secondary: #f47bff;`
- `--bg-primary: #ffffff;` `--bg-secondary: #f3f3f3;`
- `--text-primary: #020817;` `--text-secondary: #1b1b1b;`
- `--text-success: #16a34a;` `--text-error: #dc2626;`
- `--border-default: #e2e8f0;` `--border-error: #dc2626;` `--border-success: #16a34a;`
- `--radius-sm: 6px;` `--radius-md: 12px;` `--radius-lg: 12px;`
- `--shadow-sm: rgba(0,0,0,0.04) 0px 2px 8px 0px, rgba(0,0,0,0.08) 0px 8px 24px 0px, rgba(0,0,0,0.12) 0px 16px 48px 0px;`
- `--shadow-md: rgba(255,255,255,0.2) 0px -2px 1px 0px inset, rgba(255,255,255,0.1) 0px 4px 16px 0px inset, rgba(0,0,0,0.08) 0px 6px 16px 0px;`
- `--spacing-gap: 16px;` `--transition-fast: 150ms ease;` `--transition-normal: 250ms ease;` `--ease-standard: cubic-bezier(0.4,0,0.2,1);`
- `--z-dropdown: 100;` `--z-modal: 1000;` `--z-toast: 2000;`

Enforce contrast pairing: light backgrounds pair with dark text, dark backgrounds (Obsidian) pair with light text.

**1.3 Mandatory Dark Mode**
- Provide dark mode tokens under `@media (prefers-color-scheme: dark)` and a `.dark` class selector.
- Persist user theme choice via `localStorage`, falling back to `prefers-color-scheme` on first visit.
- Include a visible toggle control with correct `aria-pressed`/`aria-label`.

**1.4 Flexbox & Mobile-First**
- Use Flexbox for all layouts. Default `align-items: center` on every flex container unless explicitly justified.
- Mobile-responsive out of the box; convert rows to columns on small viewports; prevent horizontal scrolling.

**1.5 Tailwind CSS Integration**
- Use Tailwind CSS (or clean custom CSS via `@layer`/`@apply`). Utility classes must map back to CSS variables or reusable class names (`.btn`, `.card`, `.input-group`).

**1.6 Typography & Icons (Google Fonts Mandatory)**
- Text: Geist Sans (weights 400, 500, 600) via Google Fonts, bound to `--font-geistsans`. Substitute Inter if Geist unavailable. Geist Mono (weight 500) via Google Fonts bound to `--font-geistmono`. Substitute JetBrains Mono if unavailable.
- Icons: Google Material Symbols/Icons only. No inline SVGs or local icon files.

## 2. COMPONENT & SECTION SPECIFICATIONS

## 3. CORE UX & MICRO-INTERACTIONS

- Responsive by default; fluid sizing; no horizontal overflow.
- Smooth CSS transitions on all state changes (`transition: var(--transition-normal)`), respecting `prefers-reduced-motion`.
- Accessibility: sufficient contrast in both light/dark; never rely solely on color; semantic HTML5; correct ARIA roles/labels; logical focus order; full keyboard operability; `aria-live` regions for dynamic feedback.
- Mandatory visual feedback on every click/hover/submission.
- Destructive actions visually distinct in both themes.
- Button states (all via CSS classes): default (flex, align-items center, justify-content center, gap 0.5rem, min 44x44px touch target), hover (brightness/shadow + cursor pointer), focus (distinct focus ring via CSS vars), active (transform scale 0.97), loading (disabled, spinner/animated Google Icon, no dimension distortion), disabled (opacity 0.5, greyscale, cursor not-allowed), success/error (temporary feedback via `--text-success`/`--text-error`).
- Card states: default (flex, `--bg-secondary`, subtle borders/elevation), hover (elevation/shadow shift or translateY(-2px)), focus-within (highlight border), loading (skeleton shimmer), empty state (Google Icon + guidance text).
- Form/input states if any: empty, focused, filled, valid, invalid, disabled, read-only with dedicated error feedback container.

## 6. ADDITIONAL STYLE RULES (Flox Do's/Don'ts)

- Use the Iris-to-Magenta gradient (`linear-gradient(92deg, #8247ff, #f47bff)`) exclusively on the single primary CTA and on the sparkle glyph that punctuates gradient-colored words.
- Button radius 6px, card radius 12px — never mix or round further.
- Pair every gradient CTA with a solid Obsidian secondary action within 16px for the signature dual-action rhythm.
- Render code/terminal content in GeistMono 14px 500, never GeistSans.
- Use `#e2e8f0` for all structural borders/dividers at 1px.
- Display headlines at 76px with -3.5px tracking, line-height 1.0.
- Apply Rose Hot / Ember Orange accents only to the three audience pillar icons and their sub-pill labels — never to buttons or text blocks. (For this landing page, apply accent colors to feature card icons and their sub-pills only.)
- Don't apply gradient to anything other than primary CTA and decorative sparkles.
- Don't use Ember Orange or Rose Hot on buttons, text, or backgrounds — icon-accent only.
- Don't set card/button radius above 12px.
- Don't introduce drop shadows on flat content cards — triple-shadow stack reserved for terminal window and gradient CTA only.
- Don't use chromatic border on ghost nav button.
- Don't set body line-height above 1.5 or below 1.35.
- Don't apply letter-spacing to gradient CTA text or 12–14px range beyond -0.12px.
