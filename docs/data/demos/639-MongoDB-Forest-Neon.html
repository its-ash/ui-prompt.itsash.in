Frequently asked questions

How is a document database different from a relational one?expand_more
Relational databases split data across normalized tables joined at query time. CanopyDB stores each entity as one self-contained JSON document, so reads fetch everything in a single lookup and your data model matches your code.
Do I need to define a schema before inserting data?expand_more
No. Documents in the same collection can have different fields, and you can add new fields at any time. If you want guarantees, optional schema validation rules can enforce structure on writes.
How does horizontal scaling work?expand_more
You choose a shard key per collection, and CanopyDB partitions documents across nodes automatically. The balancer redistributes data as you add nodes, with no application changes required.
What consistency guarantees do I get?expand_more
Writes to a single document are always atomic. Multi-document transactions with ACID semantics are available when you need them, and read concern settings let you tune durability per operation.
Can I migrate from an existing database?expand_more
Yes. The import tooling accepts CSV and JSON exports, and the live migration service replicates ongoing writes from most relational databases so you can cut over with near-zero downtime.
What happens when I outgrow the free tier?expand_more
Upgrading from Seedling to Canopy is an in-place operation. Your connection string stays the same, storage and memory expand within minutes, and there is no data migration involved.
