SEC. 03 — HOW IT WORKS

From pencil to production in three operations.

  1. 01

    Draft

    Draw sources, transforms, and sinks on the grid. DraftLine compiles your schematic into production-grade code as you work.

  2. 02

    Review

    Open a markup pass: reviewers stamp dimensions, flag constraints, and comment directly on nodes — all tracked against REV numbers.

  3. 03

    Deploy

    Ship with one stamp of approval. Deploys are staged, diffable, and reversible, with lineage and telemetry live from the first run.

SEC. 06 — FAQ

Specification questions.

Where does DraftLine store our data and metadata?expand_more

Schematics and metadata live in your chosen region — US, EU, or AP — and pipeline data never touches DraftLine: we read contracts, not rows. Enterprise workspaces can pin residency per project.

Which sources and tools does it integrate with?expand_more

Native connectors for Postgres, Snowflake, BigQuery, Kafka, dbt, and Airflow, plus a REST API and a Terraform provider for anything homegrown.

How does schema versioning work in practice?expand_more

Every save creates an immutable REV. DraftLine diffs columns, types, and constraints line by line, flags breaking changes before review, and rolls back with one click.
