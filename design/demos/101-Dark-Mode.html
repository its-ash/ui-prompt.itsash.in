How it works

From install to insight in three steps

No rules to write, no dashboards to babysit. Nimbus earns its keep in the first week.

01

Install the agent

One line in CI — or a single Helm chart — adds the Nimbus sidecar to every service. No code changes, no config files.

02

Learn the baseline

For seven days Nimbus profiles what normal means per endpoint: traffic shape, payloads, dependencies. Thresholds tune themselves.

03

Block with reasons

Out-of-profile requests are denied at the edge and logged with a full context trace, so on-call trusts the block instead of fighting it.

FAQ

Questions we get at every demo

How does Nimbus learn what “normal” looks like?

expand_more

During a seven-day profiling window the agent builds a per-endpoint baseline of traffic shape, payloads, and dependencies. No rules, no regex — the baseline comes from your real production behavior and re-validates on every deploy.

Can Nimbus run inside our own VPC?

expand_more

Yes. On the Enterprise plan the control plane and trace store run fully self-hosted or inside your VPC. The agent is a single static binary, and no trace data ever leaves the boundary you define.

What happens when Nimbus blocks a request by mistake?

expand_more

Every block ships with a full context trace and a reason string. One click adds a scoped allow rule, and the feedback folds back into the baseline — blocks are logged, reversible, and never silent.
