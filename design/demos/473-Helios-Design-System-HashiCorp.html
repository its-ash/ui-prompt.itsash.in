From commit to cloud in three steps

The same workflow on a laptop and in CI. No separate tooling for local development.

1

Write configuration

Describe resources in HCL and commit to version control. Run nimbus fmt and nimbus validate before pushing.

2

Review the plan

nimbus plan posts a resource diff to your pull request. Reviewers see exactly what will be created, changed, or destroyed.

3

Apply with confidence

On merge, nimbus apply executes the approved plan with state locking, then records the revision for audit and rollback.

Frequently asked questions

Answers to the questions platform teams ask before rolling Nimbus out to production.

How does Nimbus store state?expand_more

State is stored in an encrypted remote backend with full version history. Operations acquire a lock before running, so concurrent applies cannot corrupt state. You can export or roll back to any revision.

Can I migrate from an existing provisioning tool?expand_more

Yes. The nimbus import command reads existing cloud resources and generates matching configuration and state. Most teams migrate one workspace at a time over a few weeks.

Which cloud providers are supported?expand_more

Nimbus ships maintained providers for AWS, Google Cloud, Azure, and Kubernetes, plus a provider SDK with a public registry of over 200 community providers.
