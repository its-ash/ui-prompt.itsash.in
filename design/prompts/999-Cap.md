# Landing Page Build Prompt — "Cap" Style Theme

## 1. Project Overview & Brand Constraint

Build a complete, responsive landing page replicating the visual language described below. **Invent a fictional brand name, product name, and all marketing copy.** Never use the real brand name "Cap", its logo, trademarks, or product names anywhere in the markup, alt text, or metadata. All copy must be original and in English.

**Deliverables:** Separate `index.html`, `style.css`, and `script.js` files. No inline `<script>` blocks beyond a single deferred entry-point reference. Enforce one consistent class-naming convention (BEM recommended) across the entire deliverable — never mix conventions. No lorem-ipsum-only submissions where real copy/labels were supplied in this prompt; placeholders allowed only where content was genuinely unspecified.

## 2. Strict Architecture Rules

### 2.1 CSS-First Architecture & Zero Inline CSS
- Keep all styling strictly inside `style.css`. Forbid the `style="..."` attribute in HTML.
- Target all design properties, layout rules, and states via class or ID selectors only.
- Keep HTML clean, semantic, and agnostic of visual styling so changing the look requires modifying only CSS.

### 2.2 CSS Variables & Theme Tokens
Store all visual tokens in `:root` (and theme classes) using CSS variables. Required tokens:

**Colors:**
`--primary`, `--secondary`, `--bg-primary`, `--bg-secondary`, `--text-primary`, `--text-secondary`, `--text-success`, `--text-error`, `--border-default`, `--border-error`, `--border-success`

Plus the full Cap palette mapped to variables:
`--color-signal-blue: #3b82f6; --color-action-blue: #2563eb; --color-ink-black: #202020; --color-carbon: #000000; --color-paper: #fcfcfc; --color-mist: #f0f0f0; --color-fog: #e0e0e0; --color-ash: #e5e7eb; --color-steel: #c2c2c2; --color-graphite: #838383; --color-slate: #646464; --color-outlined-indigo: #1e40af; --color-spark-violet: #7c3aed; --color-spark-violet-soft: #8b5cf6; --color-ember: #d97706; --color-sky: #0d74ce; --color-ice: #e0ecfc; --color-cyan-glow: #0090ff; --color-alert-red: #ef4444; --color-macos-red: #ff5f57; --color-macos-yellow: #ffbd2e; --color-macos-green: #28c840;`

**Contrast pairing:** Every light background token pairs with a dark text token and every dark background token pairs with a light text token — enforce for every theme, not just default.

**Light mode background:** Do not default to pure white; use `#fcfcfc` (Paper) as `--bg-primary`. Where a white/near-white is needed, use `#fefefe` instead of `#ffffff`.

**Border radius & shadows:** `--radius-sm`, `--radius-md`, `--radius-lg`, `--shadow-sm`, `--shadow-md` plus the Cap-specific radii: cards 12px, pills 9999px, inputs 6px, buttons 9999px, nav-bar 9999px, small-tags 2px, large-cards 16px.

**Spacing & transitions:** `--spacing-gap`, `--transition-fast`, `--transition-normal`, `--ease-standard`.

**Elevation/stacking:** `--z-dropdown`, `--z-modal`, `--z-toast`.

### 2.3 Mandatory Dark Mode Support
- Provide dark mode color tokens under `@media (prefers-color-scheme: dark)` and/or a `.dark` class selector. In dark mode, map Paper surfaces to a near-black (`#111111`–`#1a1a1a`), borders to `#2a2a2a`, text to `#f5f5f5`, and keep Signal Blue/Action Blue as accents with adjusted contrast.
- Background and text variables must switch seamlessly without HTML restructuring.
- Persist user theme choice via `localStorage`, falling back to `prefers-color-scheme` on first visit. Provide a visible toggle control with correct `aria-pressed`/`aria-label` state.

### 2.4 Flexbox Layout & Mobile-First Alignment
- Build all layout structures with Flexbox (`display: flex`).
- Every flex container must default to `align-items: center` unless an explicitly justified exception exists.
- All flex layouts must be mobile-responsive out of the box (rows → columns on small viewports). Prevent horizontal scrolling.

### 2.5 Framework Default & Tailwind CSS Integration
- Use Tailwind CSS (or clean custom CSS driven by Tailwind's `@layer`/`@apply` directives) unless another framework is requested. All utility classes must map back to CSS variables or generic reusable class names (`.btn`, `.card`, `.input-group`).

### 2.6 Typography & Icons (Google Fonts Mandatory)
- Use Google Fonts for both text and icons. Bind the geometric sans to `--font-base` (use "Inter" or "DM Sans" as the Google Fonts substitute for Cap Sans; weights 400, 500, 700). Include the `<link>`/`@import` tags.
- Use Google Material Symbols/Icons. Forbid raw inline SVGs or local icon files.

## 3. Component Design Specifications

### 3.1 Button Component
Style all states via CSS classes:
- **Default:** Flex layout (`display: flex; align-items: center; justify-content: center; gap: 0.5rem;`). Minimum touch target 44x44px.
- **Hover:** Visual shift (brightness/shadow) with `cursor: pointer`.
- **Focus:** Distinct focus ring using CSS variables (`outline`/`box-shadow`) for keyboard navigation.
- **Active/Pressed:** Click transform feedback (`transform: scale(0.97)`).
- **Loading:** Disables interactions, prevents double-clicks, renders a CSS spinner or animated Google Icon without distorting button dimensions.
- **Disabled:** Reduced opacity (`opacity: 0.5`), greyscale, `cursor: not-allowed`.
- **Success/Error:** Temporary feedback state styles driven by `--text-success`/`--text-error`.

Cap button variants:
- **Primary CTA (Blue):** 9999px pill radius, `#2563eb` background, `#fcfcfc` text, 14–16px weight 500, padding 20px/10px, subtle `0 4px 10px rgba(0,0,0,0.05)` shadow. Used for upgrade/purchase.
- **Secondary CTA (Black):** 9999px pill, `#202020` background, `#fcfcfc` text, weight 500, same dimensions. Used for download/ownership.
- **Ghost Button:** 9999px pill, transparent background, 1px `#e0e0e0` border, `#202020` text. For secondary actions (Login).
- **Outlined Action Link:** No background, underlined text or small ghost with `#1e40af` accent border. De-prioritized alternative path.
- **Button cluster rule:** Black "Download" on the left, blue "Upgrade" on the right — never invert.

### 3.2 Card Component
If interactive:
- **Default:** Flexible Flexbox layout, subtle borders and elevation using `--bg-secondary` and CSS variables.
- **Hover:** Elevation/shadow shift or subtle transform (`transform: translateY(-2px)`).
- **Focus-within:** Highlights card borders when a child link/button receives focus.
- **Loading (Skeleton):** Shimmer animation in CSS to prevent layout jumps.
- **Empty State:** Structured fallback with Google Icon and clear guidance text.

Cap card variants:
- **Feature Card:** `#fcfcfc` background, 1px `#e0e0e0` border, 12px radius, 24px padding, no drop shadow by default; optional `0 20px 25px -5px rgba(0,0,0,0.05)` lift for elevated variants. Content: image-on-top, text-below with 12px gap.
- **Download CTA Card:** `#fcfcfc` surface, 16px radius, 1px `#e0e0e0` border, ~48px vertical padding. Centered heading, two-button CTA pair, tertiary text link below. Sits inside a subtle `#e5e7eb` page background for contained-block feel.

### 3.3 Form & Input Requirements
Account for states: Empty, Focused (outline ring), Filled, Valid (success border/icon), Invalid (error border, red text, error icon), Disabled, Read-only. Structure: Flex container wrapping label, input field, and dedicated error feedback container.

### 3.4 Modal / Popup Requirements
Account for states: Opening, Open, Loading, Success/Error, Closing (all animated via CSS transitions). UX: centered flex container (`align-items: center`), backdrop overlay, Google Icon close button, keyboard focus trapping, close via `Esc` or overlay clicks.

### 3.5 Additional Cap Components
- **Floating Nav Bar:** Pill (9999px), `#fcfcfc` background, 1px `#e5e7eb` border, 1.5px inset white highlight at top edge (`rgba(255,255,255,0.2)`). Logo, nav links, GitHub star count, Login (ghost), Sign Up (black filled pill). Height ~48px, horizontal padding ~20px. Stays at top with generous viewport margin.
- **Segmented Control (Mode Selector):** Rounded container `#f0f0f0` background, ~9999px pill radius, three equal segments. Active segment: white `#fcfcfc` background, 1px `#e0e0e0` border, subtle shadow lift. Icons: lightning bolt (Instant), clapperboard (Studio), image (Screenshot). Active icon larger/bolder; inactive smaller gray `#838383`.
- **Eyebrow Badge:** 11–12px, weight 500, text `#d97706` (Ember) or `#202020`, letter-spacing 0.2em (20%), uppercase. Optionally preceded by a small 16px filled icon.
- **Product Mockup Container:** Full app window mockup with macOS traffic-light buttons (`#ff5f57`, `#ffbd2e`, `#28c840`), title bar, recording canvas. 64px circular blue `#3b82f6` play button with white triangle, ringed by soft `#e0ecfc` glow and `#0090ff` shadow halo. Recording timeline with blue progress fill. Multi-color gradients appear ONLY inside this mockup artwork.
- **Trust Logo Strip:** Horizontal row of partner/user logos at 32–40px height, monochrome gray (`#838383` or `#c2c2c2`). Preceded by caption: "Trusted by 30,000+ teams, builders and creators". Evenly spaced 24–32px gaps, left-aligned to text column.
- **Footer Link Column:** Vertical stack of 14–15px text links in `#838383`, 8px row gap. Column heading 15–16px weight 500 in `#202020`. Six columns: Product, Additional Links, (brand), Use Cases, Socials, Tools.
- **Chat Widget:** Fixed bottom-right, 48px circle, `#202020` background, white speech-bubble icon, subtle `0 10px 15px rgba(0,0,0,0.1)` shadow, sits above all content.

## 4. Core UX & Micro-Interaction Rules

- **Responsive by default:** Fluid sizing and responsive breakpoints without horizontal overflow.
- **Smooth animations:** CSS transitions on all state changes (`transition: var(--transition-normal)`), respecting `prefers-reduced-motion`.
- **Accessibility (a11y):** Sufficient contrast in both Light and Dark modes. Never rely solely on color to communicate state. Semantic HTML5 elements, correct ARIA roles/labels on custom widgets, logical DOM/focus order, full keyboard operability, `aria-live` regions for dynamic feedback (form errors, toasts, loading states).
- **Mandatory visual feedback:** Every click, hover, or submission triggers a visible state change.
- **Destructive actions:** Visually distinct in both light and dark themes.

## 8. Do's and Don'ts (Enforce Strictly)

**Do:**
- Use 9999px border-radius for all buttons, nav bar, segmented controls, and tags.
- Pair the two-button CTA cluster as black "Download" left, blue "Upgrade" right; never invert.
- Set hero/section display headings at 52–60px, weight 700, natural letter-spacing, 1.07–1.11 line-height.
- Use 0.2em letter-spacing at 11–12px weight 500 for all uppercase eyebrow labels.
- Default to white `#fcfcfc` surfaces with 1px `#e0e0e0`/`#e5e7eb` borders; shadows only on elevated cards and chat widget.
- Keep multi-color gradients exclusively inside the product mockup artwork — UI chrome stays monochrome plus one blue.
- Set page max-width 1200px with ~20px horizontal padding; hero always two-column split (text left 55%, visual right 45%).

**Don't:**
- Do not fill CTAs with any color other than `#202020` (ownership) or `#2563eb` (upgrade).
- Do not use Spark Violet (`#7c3aed`), Ember (`#d97706`), or Sky (`#0d74ce`) for buttons, links, or interactive states — decorative only.
- Do not add shadows to cards in main content flow; use 1px `#e0e0e0` border.
- Do not set body text below 14px or above 16px.
- Do not use pure `#ffffff` for page background; use `#fcfcfc`.
- Do not place multi-color gradients in buttons, badges, nav, or footer.
- Do not break the 9999px pill convention for primary actions; only valid card radii are 12px (feature card) and 16px (download CTA card).
