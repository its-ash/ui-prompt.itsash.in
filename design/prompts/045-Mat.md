## 1. STRICT RULES & ARCHITECTURE

### 1.1 CSS-First Architecture & Zero Inline CSS
- **No inline CSS:** the `style="..."` attribute is **forbidden** anywhere in the HTML.
- **Class/ID selectors only:** every visual property, layout rule, and state is targeted via class or ID selectors in `style.css`.
- **Minimal HTML modifications:** HTML stays clean, semantic, and style-agnostic — changing the theme must require editing only `style.css`.

### 1.2 CSS Variables & Theme Tokens
- Store **all** tokens in `:root` and theme classes: `--primary`, `--secondary`, `--bg-primary`, `--bg-secondary`, `--bg-sage`, `--bg-sage-alt`, `--text-primary`, `--text-secondary`, `--text-success`, `--text-error`, `--border-default`, `--border-error`, `--border-success`, `--border-accent: rgba(196,96,60,0.3)`, plus `--accent`, `--accent-deep: #9c4f1e`, `--accent-bright: #d4824a`, `--accent-strong: #C4603C`, `--wood`, `--sage-mid`, and all Section 0 tokens.
- **Contrast pairing:** every light background token pairs with a dark text token and every dark background token pairs with a light text token — enforced in **both** themes, not just the default.
- **Light mode background:** never pure white; page canvas is bone `#ede6d0`, and where a near-white surface is needed use `#fefefe` — never `#ffffff`.
- **Section rhythm:** implement alternating surfaces via two scoped classes — `.section--sage` and `.section--paper` — each of which may locally override tokens (e.g., `--border-default`, `--text-primary`) so contrast pairing holds per surface. Rhythm: Hero (sage) → Features (paper) → How It Works (sage) → Testimonials (paper) → Pricing (sage) → FAQ (paper) → Final CTA (deep sage with burnt-orange double-rule frame) → Footer (deepest sage or wood `#7a4e24`, bone text, AA-verified).

### 1.3 Mandatory Dark Mode Support
- **Note:** the style spec marks dark mode "partial" — that notation is overridden: **full dark mode is mandatory.**
- Define dark tokens under **both** `@media (prefers-color-scheme: dark)` and a `.dark` class on `<html>`, so the first paint honors the OS preference and the class acts as an explicit override. Also set `color-scheme: light dark`.
- Dark mode mapping: `--bg-primary: #232e26`, `--bg-secondary: #2e3d30`, cards on sage `#35463a`, `--text-primary: #f0e8d2`, `--text-secondary: rgba(240,232,210,0.72)`, borders `rgba(240,232,210,0.16)`, accent text `#d4824a`, wood lightened to `#8a5a2e`. The alternating rhythm persists as tonal steps between `#232e26` and `#2e3d30` — never as a jarring light flip.
- **Persistence:** read `localStorage` key `mat-theme`; fall back to `prefers-color-scheme` on first visit. Header contains a visible toggle button with a Material Symbols icon (`light_mode`/`dark_mode`), correct `aria-pressed` state, descriptive `aria-label`, and a polite `aria-live` announcement on switch.

### 1.4 Flexbox Layout & Mobile-First Alignment
- Build all layout structures with Flexbox (and CSS Grid only for card grids).
- **Default alignment rule:** every flex container defaults to `align-items: center` unless an exception is explicitly justified in a CSS comment (e.g., `align-items: stretch` for equal-height card rows).
- **Mobile-first:** rows collapse to columns on small viewports; fluid `clamp()` typography; **zero horizontal scrolling** at any width from 320px up.

### 1.5 CSS Approach
- **Exception to the Tailwind default:** the Mat spec supplies hand-authored CSS custom properties, so build with **pure, hand-authored custom CSS — no framework**. Organize `style.css` with native `@layer` in this order: `tokens` → `base` (reset, typography) → `components` (`.btn`, `.card`, `.input-group`, `.faq`, `.nav`) → `sections` → minimal `utilities`.

### 1.6 Typography & Icons (Google Fonts Mandatory)
- Load **Jost** and **Bricolage Grotesque** from Google Fonts via `<link>`; bind to `--font-base` / `--font-display`.
- Icons: **Google Material Symbols (Rounded variant)** via `<link>`; every icon is a `<span class="material-symbols-rounded" aria-hidden="true">` with descriptive text adjacent. **Inline SVGs, local icon files, and emoji icons are forbidden.**

## 2. COMPONENT DESIGN SPECIFICATIONS

### 2.1 Button Component (`.btn`, `.btn--primary`, `.btn--ghost`, `.btn--danger`)
- **Default:** `display: flex; align-items: center; justify-content: center; gap: 0.5rem;` — minimum touch target **44×44px**, Jost 500, radius `--radius-sm`. Primary = `--accent-deep` background with bone `#f0e8d2` text (pre-verified AA); ghost = transparent with `1px solid var(--border-accent)` and current-color text.
- **Hover:** brightness shift + `--shadow-sm`, `cursor: pointer`, 200ms transition.
- **Focus:** distinct `:focus-visible` ring (2px solid `--accent-bright`, 2px offset) for keyboard navigation.
- **Active/Pressed:** `transform: scale(0.97)`.
- **Loading (`.is-loading`):** disables pointer events, prevents double-clicks, swaps the label for a CSS spinner (animated border ring) or pulsing Material Symbol — **button dimensions must not change**.
- **Disabled (`.is-disabled` / `disabled`):** `opacity: 0.5`, grayscale, `cursor: not-allowed`.
- **Success/Error (`.is-success` / `.is-error`):** temporary feedback styles driven by `--text-success` / `--text-error`, always paired with an icon + text, never color alone.

### 2.2 Card Component (`.card`)
- **Default:** flexible flexbox layout, `--bg-secondary` surface (bone paper on sage sections; `#fefefe`/sage on paper sections per mode), `1px solid var(--border-default)` or `var(--border-accent)` on sage, radius `--radius-md`, `--shadow-sm`.
- **Hover:** `transform: translateY(-2px)` + `--shadow-md`, 250ms.
- **Focus-within:** card border highlights in burnt orange when a child link/button receives focus.
- **Loading (`.card--skeleton`):** shimmer animation (gradient sweep) defined in CSS to prevent layout jumps.
- **Empty state (`.card--empty`):** structured fallback with a Material Symbol and clear guidance text.

### 2.3 Form & Input (`.input-group`)
- **Structure:** flex container wrapping a `<label>`, the `<input>`, and a dedicated error-feedback element (`role="status"`, `aria-live="polite"`).
- **States — all styled via classes:** empty, focused (orange outline ring), filled, valid (`--border-success` + check icon), invalid (`--border-error`, error icon, red text message), disabled, read-only. State is never communicated by color alone — always icon + text.

### 2.4 Modal / Dialog (conditional)
- If any overlay/dialog is introduced, it must implement: opening/open/closing CSS transitions, a loading state, success/error states, a centered flex backdrop (`align-items: center`) at `--z-modal`, a Material Symbols close button, keyboard **focus trapping**, and closing via `Esc` and overlay click. If no modal is used, omit it — do not add unrequested components.

### 2.5 Page Section Specifications
- **Header (sticky):** translucent sage surface with backdrop blur, `1px` bottom rule in `var(--border-accent)`, brand wordmark, anchor nav (Features, How It Works, Pricing, FAQ), theme toggle (per 1.3), and a mobile hamburger (`aria-expanded`, menu at `--z-dropdown`). First element in DOM is a skip-to-content link. Anchor scrolling uses `scroll-behavior: smooth` + `scroll-margin-top`, disabled under reduced motion.
- **Hero (sage):** eyebrow label preceded by a 32px burnt-orange rule; H1 in Bricolage Grotesque (`clamp(2.5rem, 6vw, 4.5rem)`); supporting copy; primary `.btn--primary` + ghost anchor CTA. Desktop right side: a composition of 2–3 overlapping bone-paper cards with orange rule accents and Material Symbols icons (decorative layer `aria-hidden`); collapses below the headline on mobile. Optional: subtle CSS-only grain/radial-glow texture — static, disabled under reduced motion.
- **Features (paper):** section header (eyebrow + H2 + lede) then 3 `.card`s in a responsive grid (1 → 3 columns): orange icon tile (Material Symbol), H3, copy. All 2.2 states defined.
- **How It Works (sage):** 3 steps — oversized Bricolage numerals `01/02/03` with orange rules, title, copy — joined by a horizontal orange rule on desktop, vertical on mobile (flex row → column).
- **Testimonials (paper):** 3 quote cards: Material Symbol `format_quote` in orange, quote, CSS monogram avatar (initials in a circle — no images/SVG), name + role.
- **Pricing (sage):** 3 tiers; the middle tier is featured — elevated (larger padding / `translateY(-4px)`), `1px solid var(--border-accent)` frame, and a text badge ("Most popular") that does not rely on color alone. Each tier: name, Bricolage price, feature list with `check` Material Symbols, CTA button (featured = primary, others = ghost) with all 2.1 states.
- **FAQ (paper):** accessible accordion — each item is `h3 > button.faq__trigger` (`aria-expanded`, `aria-controls`) + `.faq__panel` (`role="region"`, `aria-labelledby`). Panel animates via the `grid-template-rows: 0fr → 1fr` technique (250ms); chevron Material Symbol rotates; fully keyboard-operable (Enter/Space); state shown via icon + ARIA, not color.
- **Final CTA (deep sage):** mid-century double-rule frame (`1px solid var(--border-accent)` with an inner offset rule), Bricolage H2, copy, and an email-capture `.input-group` + `.btn--primary`. On submit: validate email → invalid shows 2.3 error state with `aria-live` message; valid enters button loading state, then success state (check icon + "You're on the list") announced via `aria-live`. Simulate the request with a timeout — no backend.
- **Footer:** deepest sage or wood surface (AA-verified bone text), brand blurb, 2–3 secondary link columns (Product, Company, Support), social icon buttons (Material Symbols, `aria-label`, 44px targets), copyright. Links show underline on hover/focus (200ms).

## 3. CORE UX & MICRO-INTERACTION RULES
- **Responsive by default:** fluid sizing, no horizontal overflow, grids `auto-fit`/breakpoint-driven from 320px up.
- **Smooth animations:** every state change uses `transition: var(--transition-fast|normal) var(--ease-standard)`; **`prefers-reduced-motion: reduce` disables all transitions, animations, and smooth scrolling.**
- **Accessibility:** semantic HTML5 landmarks (`header`, `nav`, `main`, `section` with `aria-labelledby`, `footer`); strict heading hierarchy h1→h2→h3; logical focus order; full keyboard operability (no mouse-only interactions); `:focus-visible` styles on every interactive element; WCAG AA contrast in **both** modes; never color-only state communication; `aria-live` regions for form feedback, FAQ state, and theme changes.
- **Mandatory visual feedback:** every click, hover, and submission triggers a visible state change.
- **Destructive actions:** any `.btn--danger` must be visually distinct (error-colored border/fill + icon) in both light and dark themes.
