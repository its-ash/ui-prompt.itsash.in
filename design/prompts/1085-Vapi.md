# Vapi-Inspired Landing Page — Coding AI Prompt

## 1. Project Overview

Build a complete, responsive landing page for a **fictional** voice-AI developer platform. Invent an original brand name, product name, and all user-facing copy. **Never** use the real brand name "Vapi", its logo, trademarks, or product names anywhere in the markup, assets, or text. Reuse only the visual style system described below.

Deliverables: `index.html`, `style.css`, `script.js`. No inline `<script>` beyond a single deferred entry-point reference. No inline `style="..."` attributes. All styling lives in `style.css`.

## 2. Architecture Rules

### 2.1 CSS-First & Zero Inline CSS
- All styling in `style.css` using class/ID selectors only.
- HTML stays semantic and agnostic of visual styling.

**Typography:**

**Elevation/Z-index:** `--z-dropdown`, `--z-modal`, `--z-toast`.

### 2.3 Mandatory Dark Mode
- Provide dark mode tokens under `@media (prefers-color-scheme: dark)` and a `.dark` class selector.
- Persist user theme choice via `localStorage`, falling back to `prefers-color-scheme` on first visit.
- Include a visible toggle control with correct `aria-pressed`/`aria-label`.

### 2.4 Flexbox & Mobile-First
- All layouts use Flexbox. Every flex container defaults to `align-items: center` unless explicitly justified.
- Mobile-responsive out of the box; no horizontal scrolling.

### 2.5 Tailwind CSS Integration
- Use Tailwind CSS (or clean custom CSS driven by Tailwind's `@layer`/`@apply`). Utility classes map back to CSS variables or generic reusable class names (`.btn`, `.card`, `.input-group`).

### 2.6 Typography & Icons (Google Fonts Mandatory)
- Text: Google Font `<link>`/`@import` for Inter and Geist Mono/JetBrains Mono, bound to `--font-base`/`--font-seasonsans`/`--font-geist-mono`.
- Icons: Google Material Symbols/Icons only. No raw inline SVGs or local icon files.

## 4. Component State Requirements

### Buttons
- Default: flex, `align-items: center`, `justify-content: center`, gap 0.5rem, min 44×44px touch target.
- Hover: brightness/shadow shift, `cursor: pointer`.
- Focus: distinct focus ring via CSS variables.
- Active: `transform: scale(0.97)`.
- Loading: disabled interactions, CSS spinner or animated Google Icon, no dimension distortion.
- Disabled: `opacity: 0.5`, greyscale, `cursor: not-allowed`.
- Success/Error: temporary styles via `--text-success`/`--text-error`.

### Cards
- Default: flex layout, subtle borders, elevation via `--bg-secondary` tokens.
- Hover: `transform: translateY(-2px)` or shadow shift.
- Focus-within: highlight border.
- Loading (Skeleton): shimmer animation.
- Empty State: Google Icon + guidance text.

### Forms/Inputs
- States: Empty, Focused (outline ring), Filled, Valid, Invalid, Disabled, Read-only.
- Structure: flex container wrapping label, input, error feedback container.

### Modal/Popup
- States: Opening, Open, Loading, Success/Error, Closing (CSS transitions).
- Centered flex container, backdrop overlay, Google Icon close button, Esc/overlay close, focus trapping.

## 5. Core UX & Micro-Interactions
- Responsive by default, fluid sizing, no horizontal overflow.
- Smooth transitions on all state changes using `var(--transition-normal)`, respecting `prefers-reduced-motion`.
- Accessibility: sufficient contrast in both modes; never rely on color alone; semantic HTML5; correct ARIA roles/labels; logical focus order; full keyboard operability; `aria-live` regions for dynamic feedback.
- Mandatory visual feedback on every click/hover/submission.
- Destructive actions visually distinct in both themes.

## 6. Do's and Don'ts (Style Discipline)
- Do: 5.6px radius for cards/inputs/code blocks; 9999px for buttons and Talk-to-Vapi console; headlines at weight 300 with -0.025em tracking; Ember+Mint only as adjacent CTA siblings; Iron Border as 1px hairline; Geist Mono +0.08em for console labels; spectrogram carries all six colors.
- Don't: no drop shadows; no card radius beyond 5.6px; no spectrogram colors on UI elements; no pure white text (use Cream `#fffaea`); no more than two stacked CTA buttons; no body text below 15px; no gradients/glows/aurora.

## 7. Output Format
- Separate `index.html`, `style.css`, `script.js`.
- One consistent class-naming convention (BEM or fixed utility set) throughout — never mix.
- No lorem-ipsum-only submissions where real copy is supplied; placeholders only where content genuinely unspecified.
- All user-facing copy in English.
- All CSS variable names, class names, file names in English/ASCII.
