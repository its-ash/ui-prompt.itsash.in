# Coding AI Prompt: AWE-Themed Landing Page

## 1. Project Overview & Theme
Build a complete, production-ready landing page for a fictional autonomous-systems brand. The visual language is **"AWE"**: a near-black, gallery-like observatory aesthetic — black canvas, porcelain-white editorial type, luminous cyan details only inside imagery, mono instrument-panel labels, and flat charcoal surfaces. Invent a fictional brand name, product name, and all copy. Never use the real brand name "AWE", its logo, trademarks, or product names anywhere in the deliverable.

## 2. Strict Architecture Rules
- **CSS-First, Zero Inline CSS:** All styling lives in `style.css`. No `style="..."` attributes in HTML. Use class/ID selectors only. Keep HTML semantic and agnostic of visual styling.
- **CSS Variables & Theme Tokens:** Store all tokens in `:root` (and theme classes) using `var(--...)`. Required tokens: `--primary`, `--secondary`, `--bg-primary`, `--bg-secondary`, `--text-primary`, `--text-secondary`, `--text-success`, `--text-error`, `--border-default`, `--border-error`, `--border-success`, `--radius-sm`, `--radius-md`, `--radius-lg`, `--shadow-sm`, `--shadow-md`, `--spacing-gap`, `--transition-fast`, `--transition-normal`, `--ease-standard`, `--z-dropdown`, `--z-modal`, `--z-toast`. Enforce contrast pairing: light backgrounds pair with dark text, dark backgrounds pair with light text in every theme.
- **Light Mode Background:** Do not default to pure white; use `#fefefe` where a near-white is needed.
- **Mandatory Dark Mode:** Define dark tokens under `@media (prefers-color-scheme: dark)` and/or `.dark`. Switch background/text variables seamlessly. Persist user choice via `localStorage`, falling back to `prefers-color-scheme` on first visit. Include a visible toggle with correct `aria-pressed`/`aria-label`.
- **Flexbox & Mobile-First:** Use Flexbox for layouts. Every flex container defaults to `align-items: center` unless explicitly justified. Layouts must be mobile-responsive, converting rows to columns on small viewports. No horizontal scrolling.
- **Framework:** Use Tailwind CSS (or clean custom CSS via `@layer`/`@apply`). Utility classes must map to CSS variables or reusable classes (`.btn`, `.card`, `.input-group`).
- **Typography & Icons:** Google Fonts only. Text: Inter (substitute for Messina Sans), Cormorant Garamond (substitute for Office Times Round), IBM Plex Mono (substitute for ABC Laica Mono). Icons: Google Material Symbols/Icons. No raw inline SVGs or local icon files.

### Monumental Section Marker
Cormorant Garamond 200px/400, line-height 0.8, -6px tracking, `#e0e0e0`. Isolated on black canvas before dense module content. Not inside a card.

### Process Step Header
Full-width row: Inter 16px/400 step title `#e0e0e0` on left, IBM Plex Mono 13px/300 step metadata on right. 1px `#252525` rule separates row from description. Active numeral `#e0e0e0`, inactive `#444444`.

### Feature Module Heading
Inter 600 at 26px/31.2px with -0.52px tracking OR 32px/38.4px with -0.64px tracking. `#e0e0e0` heading, followed by 16px/1.4 Inter body in `#828b8d`.

### Framed Media Card
16px outer radius, 1px structural frame, 1px inset padding, no shadow. Visual held in `#16191b` well. 80px radius reserved for oversized image-focused compositions.

### Compact Translucent Card
`rgba(54, 61, 67, 0.4)` over `#010101`, 8px radius, no shadow, no internal padding. Contained text in `#e0e0e0` or `#828b8d`.

### Underlined Text Control
Transparent background, 0px radius, 0px padding, `#e0e0e0` text, 1px `#e0e0e0` border edge. Sparse use for terse controls (e.g., viewing an index). Not a filled pill.

### Inline Search or Command Input

### Footer Link Cluster
Compact mono labels on `#010101`. `#e0e0e0` primary text, `#646e71` counters, 8px gaps, `#252525` dividers where groups need separation.

## 5. Do's and Don'ts
**Do:**
- Use `#010101` as default page canvas; reserve `#16191b` for contained media/card interiors.
- Display statements in Cormorant Garamond 400 at 100px/100px with -3px tracking; 200px treatment only as isolated section marker.
- Messina Sans 600 (Inter 600) only at 26px or 32px feature-heading sizes with -0.02em tracking.
- Utility navigation in IBM Plex Mono 300 at 13px with 1.04px tracking, uppercase.
- `#1f1f23`-filled nav controls with 100px radius and 8px gaps.
- 1px `#252525` structural separators; cards shadowless.
- 16px card corners, 8px compact-card corners, 80px radii only for large image-led containers.

**Don't:**
- No white page backgrounds; base sections on `#010101`.
- No bright UI accent colors, saturated gradients, or semantic status-color families.
- No 16px rounded rectangles replacing 100px nav pills.
- No heavy font weights for display type; Cormorant Garamond stays 400.
- No `#e0e0e0` body copy when `#828b8d` is appropriate for explanatory paragraphs.
- No drop shadows on cards, pills, media frames, or separators.
- No padded filled primary buttons; available public controls are charcoal nav pills and transparent underlined text controls.

## 6. Surfaces, Elevation, Imagery, Layout
- **Surfaces:** Level 0 Void Canvas `#010101`; Level 1 Machine Well `#16191b`; Level 2 Charcoal Control `#1f1f23`.
- **Elevation:** Depth from nested charcoal surfaces, 1px `#252525` rules, broad blur treatments, black-to-charcoal overlays — not box shadows. Surfaces appear embedded in the void.
- **Imagery:** Cinematic 3D robot-world renders: glossy white humanoid agents with black face screens and small cyan-lit details, staged in bright seamless environments. Opening visual full-bleed and wide with cropped foreground robots framing a central figure; later visuals contained inside deeply rounded dark media wells. Monochrome compact geometric icons/marks. Imagery carries the only conspicuous cyan and functions as world-building content, not a reusable UI accent.
- **Layout:** Black full-bleed narrative canvas. Compact top header. Centered content column constrained to 940px for text-led sections. Opens with full-width high-key robot image band beneath header, then transitions into centered dark hero with large serif statement and narrow supporting copy. Subsequent sections vertically staged (not card-grid dense): oversized serif section marker introduces left-aligned process row, right-aligned step counter, divider, explanatory copy, large rounded dark media panel below. Navigation appears as standard header and as centered floating pill cluster inside later dark sections. Closes with compact link-heavy footer.

## 8. Component State Requirements
For every interactive component, style all states via CSS classes:
- **Buttons/Controls:** Default (flex, `align-items: center; justify-content: center; gap: 0.5rem`, min 44x44px touch target), Hover (brightness/shadow shift, `cursor: pointer`), Focus (distinct focus ring via CSS variables), Active/Pressed (`transform: scale(0.97)`), Loading (disabled interactions, CSS spinner/animated Material Icon, no dimension distortion), Disabled (opacity 0.5, greyscale, `cursor: not-allowed`), Success/Error (temporary feedback via `--text-success`/`--text-error`).
- **Cards:** Default (flex layout, subtle borders, elevation via `--bg-secondary` and CSS vars), Hover (elevation/shadow shift or `transform: translateY(-2px)`), Focus-within (highlight border on child focus), Loading (skeleton shimmer in CSS, no layout jumps), Empty State (Google Icon + guidance text).
- **Forms/Inputs:** Empty, Focused (outline ring), Filled, Valid (success border/icon), Invalid (error border, red text, error icon), Disabled, Read-only. Flex container wrapping label, input, and dedicated error feedback container.
- **Modals/Popups:** Opening, Open, Loading, Success/Error, Closing (CSS transitions). Centered flex container, backdrop overlay, Material Icon close button, keyboard focus trapping, close via Esc or overlay click.

## 9. Core UX & Micro-Interactions
