# Landing Page Build Prompt — AREA 17 Theme

You are an expert front-end developer. Build a complete, production-quality landing page using the **AREA 17** visual style system described below. Follow every rule in this prompt exactly. Output three separate files: `index.html`, `style.css`, and `script.js`. Use a single consistent class-naming convention (BEM) across the entire deliverable. Never mix naming conventions.

---

## 1. CSS-First Architecture & Zero Inline CSS

- All styling must live strictly inside `style.css`. **No inline CSS** (`style="..."` attributes are forbidden).
- Target all design properties via class or ID selectors only. HTML must remain clean, semantic, and styling-agnostic.
- Changing the look must require editing only CSS, not markup.

## 3. Mandatory Dark Mode Support

- Provide dark mode color tokens under `@media (prefers-color-scheme: dark)` and a `.dark` class selector.
- In dark mode: canvas becomes #1a1a1a, text becomes #ffffff, fog surface becomes #2a2a2a, cream surface becomes #2e2a26, hairline becomes #333333, electric yellow accent remains #fdf313.
- Theme switching must work via CSS variables without HTML restructuring.
- Persist user theme choice via `localStorage`, falling back to `prefers-color-scheme` on first visit. Provide a visible toggle control with correct `aria-pressed`/`aria-label` state.

## 4. Flexbox Layout & Mobile-First Alignment

- Use Flexbox (`display: flex`) for all layout structures.
- Every flex container must default to `align-items: center` unless there is an explicitly justified exception.
- All flex layouts must be mobile-responsive (rows convert to columns on small viewports). Prevent horizontal scrolling.

## 5. Tailwind CSS Integration

- Use Tailwind CSS via CDN (or clean custom CSS driven by Tailwind's `@layer`/`@apply` directives). All utility classes must map back to CSS variables or generic reusable class names (`.btn`, `.card`, `.input-group`).

## 6. Typography & Icons (Google Fonts Mandatory)

- Include Google Font `<link>` tags for Manrope (weights 400, 500) as the Suisse Intl substitute, bound to `--font-base`.
- Use Google Material Symbols/Icons for any icons. **No raw inline SVGs or local icon files.**

## 7. Theme Visual Rules (AREA 17)

- **Monochrome editorial aesthetic.** Near-black text (#1a1a1a) on pure white (#ffffff). Hairline borders (#e6e6e6). Flat surfaces. Almost no color — only one electric yellow (#fdf313) as a single bright accent.
- **Headlines carry the brand voice** through scale and tight tracking: 55px display at line-height 1.10 with -0.015em tracking.
- **Generous whitespace** (section gaps 80-192px). Full-bleed cinematic content blocks break the typographic grid.
- **Zero shadows.** Elevation via surface color shifts only (#ffffff → #f2f2f2 → #f2ede9).
- **Left-aligned** headlines and body copy. Never center-align body text or headlines.
- **8px radius** default for cards, buttons, inputs. 4px for nav. 9999px for pills only.
- **No chromatic colors** beyond #fdf313 Electric Yellow.
- **No system-ui as primary typeface.** Manrope (Suisse Intl substitute) is the workhorse.
- **Tight tracking** at all sizes; 0.004em is the loosest allowed on body text.
- **No decorative icons, flourishes, or color washes.** Typography carries 90% of visual identity.
- **No imagery wallpaper.** Full-bleed content blocks are cinematic punctuation.
- **Announcement bar** fixed to viewport bottom, full-width, #fdf313 background, #1a1a1a text.

## 8. Component Requirements

### Button
- Default: Flex layout (`display: flex; align-items: center; justify-content: center; gap: 0.5rem;`). Minimum touch target 44x44px.
- Hover: Visual shift (brightness/shadow) with `cursor: pointer`.
- Focus: Distinct focus ring using CSS variables.
- Active/Pressed: `transform: scale(0.97)`.
- Loading: Disables interactions, renders CSS spinner or animated Google Icon without distorting dimensions.
- Disabled: `opacity: 0.5`, greyscale, `cursor: not-allowed`.
- Success/Error: Temporary feedback styles via `--text-success`/`--text-error`.

Variants: **Ghost text link** (no bg, no border, Manrope 16px weight 500, #1a1a1a; hover color #949494), **Outlined button** (transparent bg, 1px solid #1a1a1a border, 8px radius; hover inverts to #1a1a1a bg with #ffffff text), **Solid neutral button** (#f2f2f2 bg, no border, 8px radius).

### Card
- Default: Flexbox layout, subtle borders, elevation via `--bg-secondary` and CSS variables.
- Hover: Elevation/shadow shift or `transform: translateY(-2px)`.
- Focus-within: Highlights card borders when child link/button receives focus.
- Loading (Skeleton): Shimmer animation in CSS.
- Empty State: Google Icon + clear guidance text.

Variants: **Fog Card** (#f2f2f2 bg, no border, 8px radius, 16-24px padding, no shadow), **Cream Feature Card** (#f2ede9 bg, no border, 8px radius, 24px padding, no shadow).

### Form & Input
- States: Empty, Focused (outline ring), Filled, Valid (success border/icon), Invalid (error border, red text, error icon), Disabled, Read-only.
- Structure: Flex container wrapping label, input field, dedicated error feedback container.
- Text Input: #ffffff bg, 1px solid #e6e6e6 border, 8px radius, 12px 16px padding, Manrope 16px weight 400 #1a1a1a, placeholder #949494. Focus: border darkens to #1a1a1a. No floating labels, no decorative icons.

### Modal / Popup
- States: Opening, Open, Loading, Success/Error, Closing (all animated via CSS transitions).
- UX: Centered flex container (`align-items: center`), backdrop overlay, Google Icon close button, keyboard focus trapping, close via Esc or overlay click.

## 9. Core UX & Micro-Interaction Rules

- **Responsive by default:** Fluid sizing, responsive breakpoints, no horizontal overflow.
- **Smooth animations:** CSS transitions on all state changes (`transition: var(--transition-normal)`), respecting `prefers-reduced-motion`.
- **Accessibility:** Sufficient contrast in both light/dark modes. Never rely solely on color for state. Semantic HTML5. Correct ARIA roles/labels. Logical DOM/focus order. Full keyboard operability. `aria-live` regions for dynamic feedback.
- **Mandatory visual feedback:** Every click, hover, or submission triggers a visible state change.
- **Destructive actions:** Visually distinct in both themes.
