# Coding AI Prompt — Landing Page (amra Style, Fictional Brand)

You are an expert front-end developer. Build a complete, production-ready landing page using a **fictional brand name, product, and copy**. Never use the real brand name "amra", its logo, trademarks, or product names anywhere in the markup, copy, or asset references. Invent original fictional content for every section.

## 1. Architecture & File Structure

- Deliver three separate files: `index.html`, `style.css`, `script.js`. No inline `<script>` blocks beyond a single deferred entry-point reference.
- **Zero inline CSS:** Never use `style="..."` attributes. All styling lives in `style.css` via class/ID selectors.
- **CSS-first:** HTML must remain clean, semantic, and agnostic of visual styling. Changing the look must require editing only `style.css`.
- **Naming convention:** Use BEM consistently across the entire deliverable. Never mix conventions.
- **No unrequested placeholders:** Where the user supplied section intent, write real fictional copy. Placeholders allowed only where content is genuinely unspecified.

## 2. CSS Variables & Theme Tokens

Define all tokens in `:root` and under `@media (prefers-color-scheme: dark)` plus a `.dark` class selector. Enforce contrast pairing: light backgrounds pair with dark text, dark backgrounds pair with light text, in every theme.

```css
:root {
  /* Colors */
  --color-ink-black: #141414;
  --color-paper-white: #fefefe;
  --color-mist-gray: #a1a1a1;
  --color-smoke-gray: #8a8a8a;
  --color-veil-gray: #d0d0d0;
  --color-periwinkle-glow: #acafff;

  /* Theme-mapped tokens */
  --primary: var(--color-periwinkle-glow);
  --secondary: var(--color-smoke-gray);
  --bg-primary: var(--color-paper-white);
  --bg-secondary: var(--color-paper-white);
  --text-primary: var(--color-ink-black);
  --text-secondary: var(--color-mist-gray);
  --text-success: #2e7d32;
  --text-error: #c62828;
  --border-default: var(--color-veil-gray);
  --border-error: var(--color-ink-black);
  --border-success: #2e7d32;

  /* Radius & Shadows (no shadow stack — radius defines surface) */
  --radius-sm: 8px;
  --radius-md: 16px;
  --radius-lg: 44px;
  --shadow-sm: none;
  --shadow-md: none;

  /* Spacing */
  --spacing-gap: 24px;
  --spacing-4: 4px;
  --spacing-8: 8px;
  --spacing-12: 12px;
  --spacing-16: 16px;
  --spacing-24: 24px;
  --spacing-32: 32px;
  --spacing-40: 40px;
  --spacing-56: 56px;
  --spacing-100: 100px;
  --spacing-104: 104px;
  --spacing-160: 160px;

  /* Transitions */
  --transition-fast: 150ms ease;
  --transition-normal: 250ms ease;
  --ease-standard: cubic-bezier(0.4, 0, 0.2, 1);

  /* Elevation */
  --z-dropdown: 100;
  --z-modal: 200;
  --z-toast: 300;

  /* Typography */
  --font-base: 'Inter Tight', sans-serif;
  --font-mono: 'Söhne Mono', 'JetBrains Mono', monospace;
}
```

Dark mode: invert surfaces — `--bg-primary` becomes `#0a0a0a`-ish near-black, `--text-primary` becomes `#fefefe`, borders become `#2a2a2a`, accent `--color-periwinkle-glow` stays. Maintain contrast pairing. Persist user choice via `localStorage`, falling back to `prefers-color-scheme` on first visit. Provide a visible toggle control with correct `aria-pressed`/`aria-label`.

## 3. Typography (Google Fonts Mandatory)

- Load Google Fonts via `<link>` or `@import`: **Inter Tight** (geometric sans substitute) and **JetBrains Mono** (uppercase label substitute). Bind to `--font-base` and `--font-mono`.
- Use Google Material Symbols/Icons. No raw inline SVGs or local icon files.
- Type scale:
  - caption: 14px, line-height 1.2, letter-spacing 0.41px
  - body: 16px, line-height 1.6, letter-spacing 0.46px
  - subheading: 20px, line-height 1.2, letter-spacing -0.2px
  - heading: 30px, line-height 1.2, letter-spacing -0.3px
  - display: 50px, line-height 1.0, letter-spacing -0.5px
- All weights 400. Never 600/700. Tight -0.01em tracking on geometric sans; +0.029em on uppercase labels.

## 4. Layout & Flexbox Standards

- Mobile-first. Use Flexbox (`display: flex`). Every flex container defaults to `align-items: center` unless explicitly justified otherwise.
- Page max-width 1200px, centered. Section gaps 100–160px. No horizontal scroll.
- Convert rows to columns on small viewports.

## 6. Component State Requirements

For every interactive component (buttons, cards, inputs, modals), implement via CSS classes:
- **Button:** default (flex, align-items center, justify-content center, gap 0.5rem, min 44x44px), hover (brightness/shadow shift, cursor pointer), focus (distinct ring via CSS vars), active (transform scale 0.97), loading (disabled, spinner, no dimension distortion), disabled (opacity 0.5, greyscale, cursor not-allowed), success/error (via `--text-success`/`--text-error`).
- **Card:** default (flex, subtle border, elevation via vars), hover (translateY -2px), focus-within (border highlight), loading skeleton (shimmer), empty state (icon + guidance).
- **Form inputs:** empty, focused (outline ring), filled, valid, invalid, disabled, read-only. Flex container wrapping label, input, error feedback.
- **Modal:** opening/open/loading/success-error/closing animated via CSS transitions; centered flex, backdrop, Material Icon close button, focus trap, Esc/overlay close.

## 7. UX & Micro-Interactions

- Smooth CSS transitions on all state changes (`transition: var(--transition-normal)`), respecting `prefers-reduced-motion`.
- Accessibility: sufficient contrast both themes; never rely solely on color; semantic HTML5; correct ARIA roles/labels; logical DOM/focus order; full keyboard operability; `aria-live` for dynamic feedback.
- Mandatory visual feedback on every click/hover/submission.
- Destructive actions visually distinct in both themes.
- No box-shadows on cards. No visible dividers between sections — spacing is the divider.

## 8. Dark Mode

- Seamless variable switching. Persist via `localStorage`, fallback to `prefers-color-scheme`. Toggle with correct `aria-pressed`/`aria-label`.
