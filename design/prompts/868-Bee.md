# Coding-AI Prompt: Complete Landing Page — "Bee" Theme (Fictional Brand Required)

## 1. Strict Rules & Architecture

### 1.1 CSS-First Architecture & Zero Inline CSS
- Keep all styling strictly inside `style.css`. Forbid `style="..."` attributes in HTML.
- Target all design properties, layout rules, and states via class/ID selectors only.
- Keep HTML clean, semantic, and agnostic of visual styling so the look can change by editing CSS alone.

### 1.2 CSS Variables & Theme Tokens
Store all visual tokens in `:root` (and theme classes) using CSS variables. Define at minimum:
- Colors: `--primary`, `--secondary`, `--bg-primary`, `--bg-secondary`, `--text-primary`, `--text-secondary`, `--text-success`, `--text-error`, `--border-default`, `--border-error`, `--border-success`.
- Contrast pairing: every light background token pairs with a dark text token and every dark background token pairs with a light text token, in every theme.
- Light mode background must not be pure white; use `#fefefe` where a near-white is needed.
- Radius & shadows: `--radius-sm`, `--radius-md`, `--radius-lg`, `--shadow-sm`, `--shadow-md`.
- Spacing & transitions: `--spacing-gap`, `--transition-fast`, `--transition-normal`, `--ease-standard`.
- Elevation/stacking: `--z-dropdown`, `--z-modal`, `--z-toast`.

### 1.3 Mandatory Dark Mode
- Provide dark mode color tokens under `@media (prefers-color-scheme: dark)` and/or a `.dark` class selector.
- Background and text variables must switch seamlessly without HTML restructuring.
- Persist user theme choice via `localStorage`, falling back to `prefers-color-scheme` on first visit; render a visible toggle with correct `aria-pressed`/`aria-label`.

### 1.4 Flexbox Layout & Mobile-First Alignment
- Build all layouts with Flexbox (`display: flex`).
- Every flex container must default to `align-items: center` unless an explicitly justified exception exists.
- All flex layouts must be mobile-responsive out of the box (rows collapse to columns on small viewports); prevent horizontal scrolling.

### 1.5 Framework Default & Tailwind Integration
- Use Tailwind CSS (or clean custom CSS driven by Tailwind `@layer`/`@apply`) unless another framework is requested. Map all utility classes back to CSS variables or reusable class names (`.btn`, `.card`, `.input-group`).

### 1.6 Typography & Icons (Google Fonts Mandatory)
- Use Google Fonts for both text and icons. Include Google Font `<link>`/`@import` tags and bind to `--font-base`.
- Icons: Google Material Symbols/Icons only. Forbid raw inline SVGs or local icon files.

## 2. Bee Theme Tokens (Implement Exactly)

### Colors
- `--color-bee-ink`: `#21200b` (headlines, body text, hairline borders, dark surface panels, outlined action borders)
- `--color-pioneer-yellow`: `#ffd900` (nav links, icon marks, colored content fields, dark-surface button text)
- `--color-lavender-memory`: `#d2c4ff` (feature-card surfaces, supporting text treatment)
- `--color-putty`: `#e5e0dd` (large card surfaces, dominant warm-gray page canvas)
- `--color-paper`: `#f7f3f1` (light card surfaces, filled light outlined-action backgrounds)
- `--color-true-black`: `#000000` (deepest media/card surface)
- `--color-white`: `#ffffff` (hero text over photography, lightest canvas)
- `--color-recruiter-indigo`: `#150a45` (full-width recruitment/announcement strip behind white text)

Map these into the generic token system (`--primary`, `--secondary`, `--bg-primary`, etc.) so dark mode can override them.

### Typography
- Display/interface face: Fff Acidgrotesk (substitute: Arial, Helvetica Neue, or Space Grotesk). Weights 400/500/700. Sizes 13/16/19/20/48/59/96px. Line heights 0.80/1.00/1.20/1.40/1.50. Letter spacing -3.19px at 96px, -0.38px at 13px, -0.19px at 19px.
- Body face: Inter Variable (substitute: Inter, Arial, sans-serif). Weights 400/500/600. Sizes 11/13/16/19/22/24/32px. Line heights 1.00/1.20/1.50/1.80. Letter spacing -0.48px at 16px, -0.38px at 13px.
- Type scale tokens: `--text-footer-nav` (Acidgrotesk 500 13px/1.5/-0.39px), `--text-body` (Inter 400 16px/1.8/-0.48px), `--text-section-label` (Acidgrotesk 700 19px/1.2/0), `--text-feature-heading` (Acidgrotesk 500 19px/1.4/-0.19px), `--text-section-heading` (Acidgrotesk 700 48px/1.2/0), `--text-editorial-heading` (Acidgrotesk 700 59px/1.2/0), `--text-hero-display` (Acidgrotesk 700 96px/1.0/-3.168px).

### Spacing & Shapes
- Base unit 4px; comfortable density.
- Spacing scale: 8/12/16/20/24/32/40/48/60/64/80/96px as `--spacing-*`.
- Border radius: cards 38.325px, links 24px, pills 1440px, badges 9999px, images 38.325px, inputs 38.325px, buttons 38.325px, darkButtons 100px.
- Section gap 40px; card padding 16px; element gap 16px.
- Elevation: none. No box shadows on cards/photo frames/purchase surfaces. Differentiate via 38.325px clipping, warm surface changes, and product imagery.

### Layout
- Editorial sequence of wide rounded modules inside a lightly framed canvas; compact top header; persistent full-width announcement strip near viewport bottom.
- Opening: full-bleed lifestyle-photo hero with oversized white display type anchored low and a compact dark video overlay near upper-right.
- Then a split yellow-copy/photography composition.
- Then a long run of large product/feature cards in Putty, Lavender Memory, Bee Ink, and black.
- Purchase section: centered pale product stage with large wearable render.
- Spacious, not dense: large image fields, centered purchase info, stacked feature areas.

## 5. Component State Requirements (Enforce for All Interactive Components)
- Buttons: Default (flex, align-items center, justify-content center, gap 0.5rem, min 44x44px), Hover (brightness/shadow + cursor pointer), Focus (distinct focus ring via CSS vars), Active/Pressed (transform scale 0.97), Loading (disabled, spinner/animated icon, no dimension distortion), Disabled (opacity 0.5, greyscale, cursor not-allowed), Success/Error (temporary feedback via --text-success/--text-error).
- Cards: Default (flex, subtle borders/elevation via vars), Hover (elevation/shadow shift or translateY(-2px)), Focus-within (highlight border on child focus), Loading (skeleton shimmer), Empty state (Google Icon + guidance text).
- Forms/Inputs: Empty, Focused (outline ring), Filled, Valid (success border/icon), Invalid (error border, red text, error icon), Disabled, Read-only. Flex container wrapping label, input, error feedback.
- Modals: Opening/Open/Loading/Success/Error/Closing (CSS transitions), centered flex, backdrop overlay, Google Icon close button, focus trapping, close via Esc/overlay click.

## 6. Core UX & Micro-Interactions
- Responsive by default; fluid sizing; no horizontal overflow.
- Smooth CSS transitions on all state changes respecting `prefers-reduced-motion`.
- Accessibility: sufficient contrast both modes; never rely solely on color; semantic HTML5; correct ARIA roles/labels; logical DOM/focus order; full keyboard operability; `aria-live` regions for dynamic feedback.
- Mandatory visual feedback on every click/hover/submission.
- Destructive actions visually distinct in both themes.

## 7. Do's and Don'ts (Enforce)
Do:
- Use Bee Ink as default text/border/dark-surface color.
- Use Pioneer Yellow as large color-block surface and as text/marks on Bee Ink surfaces.
- Hero display: Acidgrotesk 700 96px/-3.19px/1.0 line-height.
- Explanatory copy: Inter 400 16px/1.8/-0.48px.
- Clip photo frames and feature cards to 38.325px radius, no box shadow.
- 1px solid Bee Ink rules for accordion rows and outlined controls.
- 16px local gaps, 40px section gaps.

Don't:
- Don't replace Pioneer Yellow with muted gold/amber/gradient.
- Don't use drop shadows to elevate cards.
- Don't use small-radius rectangles for primary cards/media; use 38.325px.
- Don't use a filled yellow primary button; supported filled control is Bee Ink with Pioneer Yellow text.
- Don't set long paragraphs in Acidgrotesk; use Inter 400 16px/1.8.
- Don't use white body text on Paper/Putty/Pioneer Yellow surfaces.
- Don't introduce blue/pink/green interface accents alongside the yellow/lavender/putty/ink palette.

## 8. Imagery & Visuals
- Photography is primary visual material: warm, sunlit, close-cropped scenes of people wearing/handling a black wrist device; skin, fabric, food, domestic surroundings fill frame. Contained in very large rounded rectangles, often paired directly with solid yellow text panel.
- Product imagery: dark studio-like render on pale neutral ground, oversized, cropped so hardware feels physical.
- Icons sparse, compact, predominantly monochrome or Pioneer Yellow. Visuals occupy as much or more area than text in major sections.
- Use placeholder image URLs (e.g., https://picsum.photos) sized appropriately; never use real brand photography.

## 9. Fictional Brand Requirement (Mandatory)
- This spec describes the visual style of a real brand. Reuse the style only.
- Invent a completely fictional brand name, product name, and all copy. Never use the real brand name, logo, trademarks, or product names anywhere in the page.

## 10. Deliverables
- Separate `index.html`, `style.css`, `script.js`. No inline `<script>` beyond a single deferred entry-point reference.
- Enforce one consistent class-naming convention (BEM or fixed utility set) across the entire deliverable; never mix conventions.
- No lorem-ipsum-only submissions where real copy/labels are supplied; placeholders allowed only where content was genuinely unspecified.
- Use Google Fonts links for text and Material Symbols for icons. No inline SVGs or local icon files.

## 11. Dark Mode Color Strategy
- In dark mode, invert contrast pairings: dark backgrounds (Bee Ink/True Black) with light text (White/Paper), light surfaces become darker variants, Pioneer Yellow remains accent. Maintain the yellow/ink pairing identity. Ensure no white body text on light surfaces and no low-contrast combinations. Persist via localStorage with prefers-color-scheme fallback and a visible toggle with aria-pressed/aria-label.
