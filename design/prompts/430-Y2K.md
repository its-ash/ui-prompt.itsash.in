## 0. THEME SPECIFICATION — Y2K

**0.1 Color Tokens (map exactly to CSS variables):**
- `--primary`: Hot Pink `#FF1493` · `--secondary`: Electric Blue `#00BFFF` · `--chrome`: Chrome Silver `#C0C0C0`
- Accent tokens: `--accent-lime: #32CD32`, `--accent-purple: #BF00FF`, `--accent-yellow: #FFE000`, `--accent-bubblegum: #FF69B4`
- **Light mode:** `--bg-primary: #F0F0FF` (Iridescent White — never `#ffffff`; use `#fefefe` if a near-white surface is ever required), `--bg-secondary`: soft bubblegum/chrome tint (e.g., `#FDF0F8` or `#EAEAF5`), `--text-primary`: deep space purple near-black (e.g., `#1A0B2E`), `--text-secondary`: muted purple-gray (e.g., `#5A4A73`)
- **Dark mode:** `--bg-primary`: deep space (e.g., `#0D0221`), `--bg-secondary`: (e.g., `#1C1033`), `--text-primary: #F0F0FF`, `--text-secondary`: lavender-gray (e.g., `#B8A8D8`)
- `--text-success` / `--text-error` / `--border-default` / `--border-success` / `--border-error`: defined per mode with 4.5:1 contrast. Raw `#32CD32` fails on light backgrounds — use a darkened lime (e.g., `#1E8A1E`) for light-mode success text/borders; keep `#32CD32` for dark mode. Error: e.g., `#D90429` (light) / `#FF4D6D` (dark).
- **Contrast pairing is mandatory in both themes:** every light background token pairs with a dark text token; every dark background token pairs with a light text token.

**0.2 Signature Visual Effects (all CSS-only — no image assets):**
- **Chrome text:** `background: linear-gradient(135deg, silver → white → electric blue → silver)` with `background-clip: text` / `-webkit-background-clip: text` and transparent color — apply to the hero H1 and key section headings.
- **Iridescent shimmer:** animated gradient overlays (linear/conic gradients with animated `background-position` or `filter: hue-rotate()` keyframes).
- **Grunge texture:** layered `repeating-linear-gradient` / `radial-gradient` with `mix-blend-mode` — no image files, no inline SVG.
- **Bubbly shapes:** `border-radius` of 24px minimum on all cards and buttons; blob decorations via asymmetric radii.
- **Stars/sparkles:** Google Material Symbols icons (`auto_awesome`, `star`) — never inline SVG.
- **Glitch hover:** on hover, apply `filter: hue-rotate()` shift and/or short glitch keyframes (text-shadow offsets, clip-path slices), 200–400ms.
- **Y2K window frames:** cards styled as retro OS windows — 3px solid `--chrome` borders, title-bar strip with three dot controls, built from semantic HTML + CSS pseudo-elements.
- **Neon glow:** `box-shadow: 0 0 20px rgba(255,20,147,0.3)` style glows, tokenized as `--glow-pink`, `--glow-blue`, `--glow-lime`.

**0.3 Typography (Google Fonts only):**
- `--font-display`: **Orbitron** (headings, nav, buttons, prices).
- `--font-body`: **Fredoka** (formerly Fredoka One) for body copy and bubbly accents. Long paragraphs must never be set in Orbitron.
- Load via Google Fonts `<link>` tags; bind to tokens with a `sans-serif` fallback stack.

## 1. STRICT RULES & ARCHITECTURE

**1.1 CSS-First Architecture & Zero Inline CSS**
- All styling lives in `style.css`. **Forbidden:** the `style="..."` attribute anywhere in the HTML.
- Target all design properties, layout rules, and states via class/ID selectors only. HTML stays semantic and style-agnostic so a re-theme requires CSS edits only.

**1.2 CSS Variables & Theme Tokens**
- Store every token in `:root` (light defaults), overridden under `.dark` and `@media (prefers-color-scheme: dark)` (see 1.3).
- Required tokens: all colors from 0.1, plus `--radius-sm: 12px`, `--radius-md: 24px`, `--radius-lg: 36px`, `--shadow-sm`, `--shadow-md`, `--glow-pink`, `--glow-blue`, `--spacing-gap`, `--transition-fast: 150ms`, `--transition-normal: 300ms`, `--ease-standard`, `--z-dropdown: 100`, `--z-modal: 200`, `--z-toast: 300`.

**1.3 Mandatory Dark Mode Support**
- Provide full dark palettes via **both** `@media (prefers-color-scheme: dark)` and a `.dark` class on `<html>`.
- Header contains a visible toggle (Material Symbols `light_mode` / `dark_mode`) with correct `aria-pressed` and `aria-label` ("Switch to dark mode" / "Switch to light mode").
- Persist the user's choice in `localStorage`; first visit falls back to `prefers-color-scheme`. Theme switching must not require any HTML restructuring.

**1.4 Flexbox Layout & Mobile-First Alignment**
- Build all layout structures with Flexbox. Every flex container **defaults to `align-items: center`** unless an exception is explicitly justified in a CSS comment.
- All flex rows collapse to columns at breakpoints; zero horizontal scrolling at any viewport; minimum touch targets of 44×44px.

**1.5 Framework Default & Tailwind CSS Integration**
- Use Tailwind CSS (or clean custom CSS via `@layer` / `@apply`). All utilities must map back to the CSS variables; define reusable component classes `.btn`, `.card`, `.input-group`, `.window-frame`.

**1.6 Typography & Icons (Google Fonts Mandatory)**
- Google Fonts for text (Orbitron, Fredoka) and Google Material Symbols for every icon. **Explicitly forbidden:** raw inline SVGs, local icon files, emoji used as icons.

## 2. COMPONENT DESIGN SPECIFICATIONS

**2.1 Button Component Requirements** — style all states via CSS classes:
- **Default:** `display: flex; align-items: center; justify-content: center; gap: 0.5rem;` minimum 44×44px, bubbly radius, neon glow shadow. Variants: `.btn-primary` (hot-pink gradient fill), `.btn-secondary` (chrome outline, 3px `--chrome` border), `.btn-danger` (visually distinct in both themes).
- **Hover:** brightness/glow shift plus Y2K glitch or `hue-rotate()` effect; `cursor: pointer`.
- **Focus:** distinct ring via `outline` / `box-shadow` using `--secondary` for keyboard navigation.
- **Active/Pressed:** `transform: scale(0.97)`.
- **Loading:** disables interactions and prevents double-clicks; renders a CSS spinner or animated Material icon without distorting button dimensions.
- **Disabled:** `opacity: 0.5`, grayscale, `cursor: not-allowed`.
- **Success/Error:** temporary feedback styles driven by `--text-success` / `--text-error`, always paired with an icon or text — never color-only.

**2.2 Card Component Requirements** (Features, Testimonials, Pricing, FAQ):
- **Default:** flexible Flexbox layout, `--bg-secondary` surface, chrome border, 24px+ radius, Y2K window-frame styling where specified.
- **Hover:** `transform: translateY(-2px)` plus intensified glow.
- **Focus-within:** border highlights when a child link/button receives focus.
- **Loading (Skeleton):** shimmer animation defined in CSS with stable dimensions to prevent layout jumps.
- **Empty State:** structured fallback with a Material icon and clear guidance text.

**2.3 Form & Input Requirements** (newsletter signup in the Final CTA):
- Flex container wrapping a `<label>`, input field, and a dedicated error feedback container.
- **States:** empty, focused (outline ring), filled, valid (success border + check icon), invalid (error border, error text, error icon), disabled, read-only.
- Errors announced via an `aria-live="polite"` region; never color-only communication.

**2.4 Modal / Popup Requirements** (if a "plan details" or demo modal is included):
- **States:** opening, open, loading, success/error, closing — all animated via CSS transitions.
- Centered flex container (`align-items: center`), backdrop overlay, Material icon close button, keyboard focus trapping, `aria-modal="true"`, close via `Esc` and overlay click.

**2.5 FAQ Accordion Requirements:**
- Use `<details>`/`<summary>` or a fully ARIA-compliant accordion; keyboard operable; animated open/close; rotating chevron icon; logical DOM/focus order.

## 3. CORE UX & MICRO-INTERACTION RULES

- **Responsive by Default:** fluid sizing and breakpoints with zero horizontal overflow at any width.
- **Smooth Animations:** `transition: var(--transition-normal)` on all state changes. **All shimmer, glitch, glow, and floating animations must be disabled or reduced under `prefers-reduced-motion: reduce`.**
- **Accessibility (a11y):** 4.5:1 text contrast in both Light and Dark modes — darken lime/cyber-yellow for light-mode text; use raw neon hues only for fills and decoration where contrast-safe. Never rely on color alone to communicate state. Semantic HTML5 elements, correct ARIA roles/labels on custom widgets, logical focus order, full keyboard operability, and `aria-live` regions for dynamic feedback (form errors, loading, toasts).
- **Mandatory Visual Feedback:** every click, hover, and submission triggers a visible state change.
- **Destructive Actions:** `.btn-danger` must be visually distinct in both light and dark themes.
